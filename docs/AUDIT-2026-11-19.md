# Pagecrane: Edge-Case, UX & Security Audit

**Date:** 19 Nov 2026 · **Build audited:** working tree after the Tools & Files / Resize Pages work (app ID `com.theairsolanki.pagecrane`, Flutter 3.50, release APK + iOS release).
**Method:** source review of every flow; the merged **release** Android manifest dumped with `aapt`; behaviour observed on the Android 16 emulator and an iPhone 16 Pro during this session (camera, crop, compress, merge with real locked and damaged PDFs, permission denial, multi-select, resize). Findings marked *(code)* come from reading the source, not a reproduced crash.

Legend: ✅ handled today · ⚠️ gap · ❌ broken

## 1. Executive summary

Pagecrane has a small attack surface. It has no backend, no accounts, no deep links and no share-in intents. Its only exported component is the launcher activity, and its only platform channel takes no arguments. Imported PDFs are re-rendered to images, which strips JavaScript, links, forms and attachments. The weak points are elsewhere:

1. **Privacy promise vs. backups.** The UI says "kept on this device" and "nothing is uploaded", yet every scan is included in iCloud Backup and Android Auto Backup by default.
2. **Data-loss windows.** Compress, Reorder and Resize overwrite a document's pages in place, with no rollback.
3. **Memory exhaustion.** Oversized images, very long PDFs and big batches can crash the app with OOM (out-of-memory) errors.

None of these is remotely exploitable for code execution today, but each is user-visible and two of them can lose or leak sensitive documents.

### Top risks (ranked)

| # | Severity | Risk | Where |
|---|---|---|---|
| 1 | **High** | Scanned IDs, tax and medical PDFs are **included in iCloud / Google Drive device backups**, contradicting the "on this device / nothing is uploaded" copy | `DocRepository.open()` stores in AppDocuments; Android `allowBackup` defaults to true (merged manifest has no override); iOS Documents is backed up by default |
| 2 | **High** | **Non-atomic page replacement**: if the app is killed or the disk fills during Compress, Reorder, Resize or Annotate, a document is left with missing or mismatched pages and a stale `pageCount` | `DocRepository.replacePages()` deletes old pages, then writes new ones; the index is committed last |
| 3 | **High** | **Decompression bomb / huge image → OOM crash.** Images are fully decoded before any size check; a 20 000 × 20 000 PNG of a few hundred KB needs about 1.6 GB of RAM | `page_pipeline.dart` `_decode()` → `_fit()` (import photos, Files images, Image tools) *(code)* |
| 4 | **High** | **Unbounded memory for big documents and batches.** Review keeps three JPEGs per page in RAM (original + source + preview), and merge, compress and resize load every page at once (`Future.wait`). A 1 000-page imported PDF renders everything into a list | `ScanSessionNotifier`, `DocRepository.readPages`, `PdfImporter.render` *(code)* |
| 5 | **Medium** | **Untrusted PDFs are parsed by native PDFium in-process.** A parser memory-corruption bug becomes an app crash or worse | `pdfrx` (Import PDF, Merge from Files) |
| 6 | **Medium** | **Plaintext copies left in caches**: file_picker copies, image_picker copies, share_plus temp files, the system-scanner cache on its failure path | `ScannerBridge`, `PdfImporter.pick`, `shareDocs`, Export images |
| 7 | **Medium** | **Disk full and I/O errors are unhandled** in the data layer, leading to spinners that never stop, unhandled exceptions and orphan `d…` folders | `DocRepository._writeContents`, `DocumentsNotifier.*` (no try/catch in `documents/data`) |
| 8 | **Medium** | **Over-broad release permissions**: `INTERNET`, `ACCESS_NETWORK_STATE`, `RECORD_AUDIO`, `READ_EXTERNAL_STORAGE` are merged in from plugins. They hurt the Play Data-safety form, user trust and the "offline" claim | merged release manifest |
| 9 | **Medium** | **Import errors are swallowed.** One undecodable image (corrupt, or HEIC via Files) aborts the whole import with no message | `startScan` only catches `ScannerUnavailable` |
| 10 | **Medium** | **No app lock and no app-switcher privacy**: an ID scan stays visible in the recents thumbnail; no biometric gate | app-wide |
| 11 | Low | 0-page outcome crashes the save (`pages.first` on an empty list), e.g. merging only empty PDFs | `DocRepository._writeContents` *(code)* |
| 12 | Low | iOS file protection is the default (`CompleteUntilFirstUserAuthentication`), not `Complete` | iOS entitlements |
| 13 | Low | `debugPrint` of camera exceptions ships in release logs; no Dart obfuscation or split debug info | `camera_scan_screen.dart`, build commands |
| 14 | Low | Document names aren't sanitised (slashes, newlines, 1 000-char names, RTL control characters); shared PDF filenames use the raw name | `renameDoc`, `shareDocs` |
| 15 | Low | `NSPhotoLibraryAddUsageDescription` is declared but nothing saves to Photos (App Review may ask) | `Info.plist` |

## 2. Edge-case matrix

### 2.1 Camera, scanning and edge detection

| Scenario | Flow | Failure mode / impact | Expected behaviour | Today |
|---|---|---|---|---|
| Low light | Live camera | Otsu threshold contrast drops below 35, so no outline appears and auto-capture never fires | Chip says "More light needed"; suggest flash; manual shutter still works | ⚠️ manual works, no hint |
| Glare / hot-spot on glossy paper | Live camera | Bright blob merges with the glare, so the outline overshoots | Detect a saturated region and hint "Tilt to avoid glare"; crop editor fixes it after | ⚠️ crop editor only |
| White paper on a white desk | Live camera | No contrast → no outline | "Place on a darker surface" hint after 3 s with no quad; manual capture → whole photo + crop editor | ⚠️ partial |
| Patterned / busy background | Live camera | Largest bright blob may be the background | `plausibleQuad` rejects twisted shapes ✅; add a hint | ✅ / ⚠️ |
| Open notebook (two pages) | Live camera | Previously selected both pages | Gutter split keeps the page under the centre | ✅ fixed this session |
| Wrinkled / curved page | Capture | 4-point warp can't flatten a curve; text bows | Document the limitation; offer "Original" filter; future: curve dewarp | ⚠️ |
| Multi-column / tiny text | Capture | Pages are captured at 1080p, so 6 pt text may be soft | Offer higher-resolution capture (photo at max preset, stream at 720p) | ⚠️ |
| No document in frame | Live camera | No auto-capture; manual shot keeps the whole photo, uncropped | ✅ toast "kept uncropped" + crop editor | ✅ |
| Permission denied | Camera | — | Permission card with **Open Settings** and **Import from Files**; no double prompt | ✅ fixed this session |
| iOS "Limited Photos" access | Import photos | Picker shows only the selected subset; user is confused why photos are missing | Explain limited access; the system picker is already used (needs no permission) | ✅ picker / ⚠️ copy |
| Camera in use by another app / hardware missing | Camera | `CameraException` | "Camera couldn't start" card: Try again / Import / Use system scanner | ✅ |
| Rotation lock / device rotated | Camera | Camera screen is locked portrait; Android frames rotated by sensor; iOS frames pre-rotated | ✅ handled by frame shape | ✅ |
| Rapid shutter taps | Batch capture | `_capturing` guard drops taps; each shot starts its own isolate → memory spike while many are in flight | Queue at most 2 pending processing jobs; show a "processing" badge | ⚠️ |
| 50+ pages in one batch | Camera | Hard cap of 50 ("Page limit reached") | Raise the cap after moving originals to disk; tell the user why there's a cap | ⚠️ |
| 200-page review session | Review | Original + source + preview held in RAM → about 300–600 MB → OOM on 3–4 GB phones | Keep originals and sources on disk (session temp dir); keep only visible previews in memory | ❌ *(code)* |
| Thermal throttling during a long batch | Camera | Image stream runs at 30 fps while only every 80 ms is used | Lower stream fps / resolution; pause detection when the dock is open | ⚠️ |
| App backgrounded mid-capture | Camera | Camera released and restarted on resume; in-flight `compute` continues | ✅ | ✅ |

### 2.2 PDF operations

| Scenario | Flow | Failure mode / impact | Expected behaviour | Today |
|---|---|---|---|---|
| 0-page PDF imported | Import PDF | "Import cancelled" toast (misleading) | "This PDF has no pages" | ⚠️ |
| Merge only 0-page PDFs | Merge | `pages.first` on an empty list → unhandled `StateError` | Block with an issue card "Nothing to merge" | ❌ *(code)* |
| 1-page document | Split / Reorder | Split "every 1 page" → 1 output; Reorder has nothing to drag | Disable Reorder for 1 page; Split explains | ⚠️ |
| 800-page PDF import | Import / Merge | Every page rendered into one in-memory list → OOM; long blocking import | Cap (e.g. 300 pages) with a warning; stream pages to disk as rendered | ❌ *(code)* |
| Truncated / malformed PDF | Import / Merge | PDFium error → "Couldn't open this PDF" or the Merge issue card | ✅ shown with file name | ✅ (merge verified) |
| `.exe` / `.jpg` renamed to `.pdf` | Import / Merge | PDFium rejects it → same as damaged | ✅ | ✅ |
| Password-protected PDF | Import / Merge | Password prompt; Unlock & retry in Merge | ✅ (verified with a real encrypted PDF) | ✅ |
| Owner-password / permission-restricted (no user password) | Import | PDFium opens and renders, ignoring "no copy/print" flags | Product decision: respect restrictions or warn the user | ⚠️ |
| "Under 50 KB" on a dense 20-page scan | Target KB | Plan can't fit → amber "Can't reach 50 KB · smallest ~X" warning; running still produces the smallest readable result | ✅; also offer "Split into parts under 50 KB" | ✅ / ⚠️ |
| Already heavily compressed file | Compress / Target | Re-encode would grow → `_keepIfSmaller` keeps the original, toast says so | ✅ | ✅ |

| Huge-megapixel / panorama photo (12 000 × 3 000) | Import / Image tools | Full decode before downscale; at 50 MP+ that means OOM | Read the header first; reject > 40 MP or decode with a scale factor | ❌ *(code)* |

| Signature on a rotated page | Sign | Rotation is applied before storage, so stored pages are upright and annotation is drawn in page space | ✅ (verify with a landscape page) | ✅ *(code)* |
| Pages of mixed sizes | Merge / Resize | Merge keeps each page's own size; Resize normalises to A4/Letter/Legal | ✅ | ✅ |
| Resize a landscape page | Resize Pages | Gets landscape paper ✅; preview always shows portrait paper | Preview should follow page 1's orientation | ⚠️ |

### 2.3 Storage, search, state and lifecycle

| Scenario | Flow | Failure mode / impact | Expected behaviour | Today |
|---|---|---|---|---|
| Disk full mid-save | Review Save / Merge / Compress | `FileSystemException` unhandled → spinner never stops / red error; orphan `PDFit/d…` folder | Pre-check free space (pages × ~600 KB); catch, clean up, explain "Free up 40 MB" | ❌ *(code)* |
| App killed during Compress / Reorder / Resize / Annotate | Any rewrite | Old pages deleted, some new pages written, index still says the old `pageCount` → broken document | Write to `d…/.staging`, then atomic swap + index commit; recovery sweep on launch | ❌ *(code)* |
| App killed between page write and index commit (new doc) | Save / Merge | Orphan folder not in index; disk leak | Launch sweep: delete folders not in index | ⚠️ |
| Corrupt `index.json` | Launch | Treated as empty library (documents become invisible but stay on disk) | Rebuild the index from folders; keep a `.bak` copy | ⚠️ |
| 0 documents | Home / Files / Tools | ✅ first-run empty states | — | ✅ |
| Search with no matches / regex characters (`.*`, `(`) | Files | Plain `contains`, so no regex evaluation | ✅ no-results card with filters | ✅ |
| Very long name / emoji / RTL characters | Rows, share | Rows wrap to 2 lines ✅; shared PDF filename uses the raw name (slashes, newlines) | Sanitise on rename (trim, max 120, strip control and bidi characters); sanitise share names like Export already does | ⚠️ |
| Large accessibility text (200%) | All | Fixed-height controls (camera dock 44/72/84 pt, segmented 44 pt, chips) may clip or overflow | Audit at 1.5× and 2×; use `minHeight` not `height`; `FittedBox` only for labels | ⚠️ |
| RTL locale | All | Layouts use `EdgeInsets.fromLTRB` / `Alignment.centerLeft` (not directional); the app is English-only | Switch to `EdgeInsetsDirectional`; localise strings | ⚠️ |
| Theme switch mid-flow | All | Tokens read from the theme each build | ✅ | ✅ |
| Rapid repeated taps | Save / Merge / Compress / Delete | Buttons are disabled while busy ✅; Delete confirm dialog prevents double delete ✅ | — | ✅ |
| Review Save tapped twice quickly | Review | Sheet-based save; verify the second tap is blocked while `renderAll` runs | Disable Save while rendering | ⚠️ verify |

## 3. UX, UI and product improvements

| Priority | Improvement | User impact |
|---|---|---|
| P1 | **Honest privacy copy plus a "Back up my documents" setting (off by default).** | Matches the on-device promise; users with IDs and tax records aren't surprised by cloud copies |
| P1 | **Live-camera guidance chips**: "More light", "Avoid glare", "Darker background", "Hold steady". | Fewer failed auto-captures; less trial and error |
| P1 | **Undo for destructive actions** (Delete, Compress, Resize, Reorder): keep the previous version for 10 s with an Undo snackbar, or a "Revert" entry in the document menu. | Mistakes become recoverable, and this pairs naturally with the atomic-write fix |
| P1 | **Size warning before Compress / Target KB on mixed documents** ("estimate based on 3 sample pages"). | Fewer surprised "it's still too big" moments |
| P2 | **"Split into parts under N KB"** when a target can't be reached (common for e-filing portals). | Converts a dead end into a successful submission |
| P2 | **Remember the last Target KB and paper size** per user. | Faster repeat tasks (the same portal every month) |
| P2 | **App lock (Face ID / fingerprint) and hide content in the app switcher** (Settings toggle). | Protects IDs on a shared or unlocked phone |
| P2 | **Batch scan: show a pending-processing count on the thumbnail strip**, and allow capture while processing. | Faster scanning of long documents |
| P2 | **Import errors as a per-file summary** ("8 imported · 1 skipped: HEIC not supported"). | Users know what happened instead of a silent nothing |
| P2 | **Search inside documents (OCR)** on device (ML Kit / Vision). | Search finds "tax_2025" content, not just names |
| P3 | **Large-text and RTL pass** (directional insets, `minHeight` controls, localisation). | Accessibility and international markets |
| P3 | **Tablet layout** (two panes in Tools & Files, constrained width). | Polish on iPad and foldables |
| P3 | Haptics and motion: respect "Reduce Motion" for the flash and glow effects. | Accessibility |

**Accessibility snapshot:** custom widgets added this session have semantics labels, 44 pt targets and ≥ 4.5:1 contrast (issue card, progress card, chips, selection bar). Older screens still contain some 11 pt muted labels; check them against 4.5:1 in dark mode.

## 4. Security findings and remediations

| ID | Vulnerability / risk | Attack vector / exposure | Concrete fix |
|---|---|---|---|
| S-1 (High) | Sensitive documents included in OS backups | Anyone with the user's iCloud / Google account (or a compromised backup) can restore the scans; this contradicts the app's claims | **Android:** set `android:allowBackup="false"` and `android:dataExtractionRules` excluding `files/app_flutter/PDFit` (API 31+), plus `fullBackupContent` for ≤ 30. **iOS:** set `URLResourceKey.isExcludedFromBackupKey = true` on `Documents/PDFit` at startup (tiny method channel in `AppDelegate`). Offer an opt-in toggle |
| S-2 (High → integrity) | Non-atomic rewrite → corrupted documents | Crash, kill or disk-full during Compress / Resize / Reorder / Annotate | In `replacePages`: write pages + thumb + PDF into `dirOf(id)/.staging/`, `flush`, then rename-swap the directory and commit the index; on launch delete `.staging` and orphan folders |
| S-3 (High → DoS) | Decompression bomb / oversized images | Malicious or accidental image via Photos / Files → OOM kill | Before `decodeImage`: `final info = img.findDecoderForData(bytes)?.startDecode(bytes); if (info == null \|\| info.width * info.height > 40e6) throw TooLarge`. Also cap input files at ~50 MB |
| S-4 (High → DoS) | Unbounded page counts in memory | 1 000-page PDF, 200-page review session | Page cap with warning (e.g. 300); stream rendered pages to disk; `readPages` in chunks; keep review originals in a session temp dir |
| S-5 (Medium) | Native PDFium parsing untrusted PDFs | Crafted PDF → memory corruption in-process | Keep `pdfrx` / PDFium current (track releases; Dependabot / `flutter pub outdated` in CI); cap file size and page count before rendering; the current rasterise-on-import design already **strips JS, actions, links, forms and embedded files** (good, keep it); never render PDF annotations' remote content |
| S-6 (Medium) | Plaintext residue in caches | Forensic extraction / backups of cache dirs; copies of tax PDFs persist after import | Call `FilePicker.clearTemporaryFiles()` after import / merge; delete image_picker results after processing; wipe `share_plus` and `XFile.fromData` temp files after share completes; call `CunningDocumentScanner.cleanCache()` in a `finally`; sweep `getTemporaryDirectory()` on launch |
| S-7 (Medium) | Over-broad permissions | Store listing / Data-safety mismatch ("app can access the internet and microphone") | In `AndroidManifest.xml` add `xmlns:tools` and `<uses-permission android:name="android.permission.RECORD_AUDIO" tools:node="remove"/>` (audio is never recorded; `enableAudio:false`), likewise `READ_EXTERNAL_STORAGE` (the system pickers need none). Evaluate removing `INTERNET` / `ACCESS_NETWORK_STATE`: the app itself makes no network calls (verified: no HTTP client; only `launchUrl` to the browser), but test the ML Kit scanner fallback without them first |
| S-8 (Medium) | Unhandled I/O and import exceptions | Disk full, bad image → unhandled errors, stuck UI, partial state | Wrap data-layer writes in try/catch → typed errors → issue card; per-file import errors |
| S-9 (Medium) | No at-rest app gate / recents snapshot | Shoulder-surfing, shared device | Optional biometric lock (`local_auth`); Android `FLAG_SECURE` toggle; iOS blur overlay on `sceneWillResignActive` |
| S-10 (Low) | iOS data-protection class | Files readable after first unlock (e.g. by a forensic tool on a seized, unlocked-once device) | Add entitlement `com.apple.developer.default-data-protection = NSFileProtectionComplete` (no background processing needed, so it's safe) |
| S-11 (Low) | Release logging and build hygiene | `debugPrint` ships to logcat; symbols not obfuscated | Guard logs with `kDebugMode`; build with `--obfuscate --split-debug-info=build/symbols` and keep the symbols privately; R8 is on by default for release |
| S-12 (Low) | Name injection into filenames | Shared PDF named with `/`, newline or bidi characters can confuse receivers or spoof extensions (`invoice‮fdp.exe`) | Sanitise on rename and share: strip control and bidi (`‪-‮`, `⁦-⁩`) characters and `\\/:*?"<>|`, trim to 120 characters |
| S-13 (Low) | Unused photo-add permission string | App Review query; unnecessary capability claim | Remove `NSPhotoLibraryAddUsageDescription` until "Save to Photos" exists |
| S-14 (Info) | IPC / deep-link surface | Only the launcher activity is exported; FileProviders are `exported=false`; no URL schemes; `pagecrane/system` channel takes no arguments | ✅ No action. **If** share-in or "Open in" is added later: allow-list MIME types, cap size, copy into the sandbox before parsing, never trust provided filenames |
| S-15 (Info) | Numeric input validation | Target KB (`digitsOnly`, 6 digits, clamped), page ranges (`int.parse` overflow → FormatException, bounds checked before looping) | ✅ Verified; add fuzz tests |
| S-16 (Info) | Network / telemetry | No analytics, crash SDK or HTTP client in `pubspec`; no PII leaves the device through the app | ✅ Keep a CI check that fails if an HTTP / analytics package is added without review |
| S-17 (Info) | Secrets and signing | Upload keystore outside the repo; `key.properties` git-ignored; release signed with the upload key | ✅ Back up the keystore offline; enable Play App Signing |

## 5. QA and security test checklist

**Camera and scanning**
- [ ] Deny camera → card shows once (no second system prompt) → Open Settings lands on Pagecrane → allow → return → camera starts.
- [ ] Revoke camera while the app is backgrounded → resume → card, no crash.
- [ ] Open the camera while another app holds it → "couldn't start" card → Try again works after the other app closes.
- [ ] Hold a page still for 1.1 s → exactly one auto-capture; turn the page → next capture; leave it → no duplicate.
- [ ] Open notebook, aim at the right page → outline excludes the left page.
- [ ] Tap the shutter 20× fast → no crash; page count equals the accepted captures.
- [ ] Batch of 50 → "Page limit reached"; memory < 400 MB (Android Studio profiler / Xcode).
- [ ] Low light, glare, white-on-white → manual capture works; crop editor fixes the corners.

**PDF operations**
- [ ] Import: valid, 0-page, truncated, renamed `.exe`, password (right / wrong / cancel), owner-restricted PDFs → correct message each time, no crash.
- [ ] Merge: library + locked (Unlock, then Remove & Retry) + damaged + 0-page-only → issue card, never a crash.
- [ ] Merge 300+ pages → progress and Cancel work; memory stays bounded (after S-4).
- [ ] Target 50 KB on a dense 20-page scan → amber warning; run → smallest readable result, honest toast.
- [ ] Compress an already-small file → original kept, "already as small" toast.
- [ ] Resize A4 → Letter → Legal, portrait and landscape pages; open the exported PDF in Acrobat / Preview and check the page size (8.5 × 11 in etc.).
- [ ] Sign a landscape page and a rotated page → signature position matches the preview.

**Storage and lifecycle**
- [ ] Fill the device to < 50 MB free → Save / Merge / Compress show a clear error, no orphan folder (after S-8).
- [ ] Kill the app (`adb shell am kill`) mid-Compress / Resize / Reorder → relaunch → document intact: old or new, never mixed (after S-2).
- [ ] Corrupt `index.json` (adb on a debug build) → documents recovered from folders (after the fix).
- [ ] Rename to 300 characters, emoji, `a/b`, RTL text, `‮` → UI wraps; shared filename is sanitised.
- [ ] Font scale 200% (iOS Larger Text / Android font 2.0) → no clipped buttons on Camera, Compress, Tools & Files, Merge.
- [ ] Switch to Arabic (RTL) → layout mirrors sensibly (after the directional-insets pass).

**Security**
- [ ] `adb shell bmgr backupnow com.theairsolanki.pagecrane` → backup excludes `PDFit/` (after S-1); iOS: check the Settings › iCloud › Backups size for Pagecrane.
- [ ] Inspect `cache/` and `tmp/` after import, merge, share and export → no leftover document copies (after S-6).
- [ ] Release APK `aapt dump permissions` → no `RECORD_AUDIO` / `READ_EXTERNAL_STORAGE` (after S-7).
- [ ] Proxy all traffic (mitmproxy) for a full session → zero requests from the app (the browser footer link excepted).
- [ ] Import a 20 000 × 20 000 PNG bomb and a 12 000 × 3 000 panorama → rejected or downscaled, no OOM (after S-3).
- [ ] Fuzz page-range and KB fields (empty, `-`, `999999999999999999999`, unicode digits) → validation message, no crash.
- [ ] `logcat` during a camera failure on a release build → no stack traces (after S-11).
- [ ] App switcher shows a blurred / blank snapshot when the privacy toggle is on (after S-9).

### Suggested fix order
1. **S-2** atomic writes + launch recovery, and **S-8** error handling (prevents data loss).
2. **S-1** backup exclusion + honest copy (keeps the privacy promise).
3. **S-3 / S-4** decode guard, page caps, review originals on disk (crash resistance).
4. **S-6 / S-7** cache cleanup + permission trimming (store listing and Data-safety form).
5. UX P1 items, then S-9 app lock, then the large-text / RTL pass.
